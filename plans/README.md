  the durable `agent_completed` event.
- Add task delivery state or import notifier DETS state: rejected because only new completion events
  enqueue jobs; historical completions cannot replay.
- Enqueue from `TaskChannel.finalize_turn/3`: rejected because it is a socket/PubSub consumer and may
  be absent after client disconnect; the durable interaction transaction is authoritative.
- Send one lifetime summary per task: rejected in favor of one job per `{task_id, turn_number}`, which
  matches the event the user requested and supports multiple completed turns.
- Delete Frontman Notifier: rejected because it still owns GitHub stargazer alerts.
- Increase interactive tool deadlines: rejected because human delay is not execution failure.
- Add durable pause events or worker-retirement timers: rejected for Plan 002 because they require
  additional batch-recovery and handoff mechanisms. Existing parked execution plus history recovery is smaller.
- Remove every timeout: rejected because transport, provider, finite tool execution, and human input have different lifetimes.
- Delete the runtime `:finishing` handoff: rejected because commit `b54232d9` fixes a real completion-registration race.
- Reinterpret historical `agent_paused` rows as active: rejected because their tool calls already contain terminal error results.
